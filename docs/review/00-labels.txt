===============================================================================
WHERE THE OLD NUMBERS CAME FROM, AND WHETHER THEY WERE EVER CANONICAL
===============================================================================
They were canonical — for one commit.

The panel showed 3 / 6 / 8 / 10 / 15 / 30. Those are EXACTLY CAR_TYPES' base HP
values as of 0f4b7fa, the commit that added the panel:

    small 3 · big 6 · jeep 8 · truck 10 · bigrig 15 · tank 30

A later balance pass took them to 2 / 4 / 5 / 7 / 11 / 20 and the panel's copy
never followed. So this was not an invented third set — it was a correct snapshot
that went stale. The file even carried the instruction:

    "Keep the HP numbers in sync with src/director/CarTypes.js"

That is the whole failure. A comment is not a mechanism. This is the same
stale-copy class as the bomb-slot desync (three copies of "where is slot N") and
the merged-bomb sprite table.

The second problem was independent of the drift: "base values, scales by level" is
not usable information even when the base values are right. A player looking at a
4 HP van cannot derive it from an 8, because hpMultiplier is never shown anywhere
in the game.

===============================================================================
THE FIX
===============================================================================
CarTypes gains two canonical exports:

  carHpFor(type, hpMultiplier)
      Math.max(HP_MINIMUM, Math.round(base * mult)) — the exact expression the
      spawner used. It existed as FOUR copies (CarDirector._buildCar,
      GameLoop._primeInitialCars, SimulationRunner's initialCars path, and the
      panel's table). All four now call this one function.

  spawnableTypesFor(level, gridRows, cfg)
      Union of the band-weight table, spawnScript stage weights, initialCars, and
      the carry-over bait pair — then filtered by minSpawnRow against board depth.
      GameApp._levelCarTypes (the level-start intro cards) delegates to it, so the
      manual and the intro cards cannot disagree about what a level spawns.

The panel reads live level context at open time (levelId, gs.world.hpMultiplier —
the DDA-adjusted value actually being spawned from, not the base config —
gridRows, and the level cfg).

REACHABILITY, since it was asked: the panel CANNOT be opened outside a level. Its
🚗 button lives on the goal bar and its visibility is tied to the pause button, so
it only exists during gameplay. No main-menu or level-select entry point exists.
The no-level branch is therefore defensive only, and it shows "Start a level to
see its car HP" rather than falling back to base values — which would reintroduce
exactly the number the player cannot use.

===============================================================================
ONE HONEST LIMITATION, NOT FIXED
===============================================================================
Carry-over bait/reward cars (CarDirector._buildCarryOverCar) are type 'small' with
hp 1-2 REGARDLESS of hpMultiplier, and carry no flag distinguishing them. So an
occasional bike on the road has 1 HP while the manual's Motorbike row says 2.

This is the bait mechanic, not manual drift — those cars deliberately sit below
HP_MINIMUM so a dmg>=2 shot can chain-kill the pair. The manual documents TYPES,
and a bait car is a type-'small' car with off-table hp. Flagging it because it is
the one case where the panel and the board can still disagree, and closing it
would mean either giving bait cars their own manual row or tagging them in the
model — both design decisions, not fixes.

===============================================================================
GUARD TEST — tests/car-manual-hp.test.js (6 tests)
===============================================================================
Asserts the panel against ACTUALLY SPAWNED CARS, not against CAR_TYPES. Checking
the panel against CAR_TYPES is what the old comment already promised; it is the
mirror-checks-mirror shape that let this ship.

  - spawns real cars through CarDirector across 8 levels x 6 hpMultipliers
    (0.70/0.81/0.89/0.90/1.0/1.5) x gridRows 8 and 16, and asserts every spawned
    car's hp equals what the manual would print for its type
  - asserts no type SPAWNS while being listed unavailable (this caught a real
    hole: L30's weight table has no 'small', but bait bikes appear there anyway)
  - pins L9 not listing Tank and L30 listing it
  - pins the HP_MINIMUM clamp
  - asserts the overlay contains no `hp: <number>` literal and no "base values"
    footer, so the hardcoded table cannot come back
  - asserts every CAR_TYPES entry has a row, so a new type cannot render blank

The bait-car exclusion in that test is deliberately ONE-DIRECTIONAL: it skips only
smalls whose hp is BELOW the computed value, so a car with MORE hp than the manual
shows still fails.
