TWO DEFECTS. ONE IS FIXED, ONE IS AN ART PROBLEM I CANNOT FIX WITHOUT NEW ART.

===============================================================================
1. TINY MOTORBIKES — FIXED
===============================================================================
Cause: L1, L2 and L3 were still gridRows 16. Every other level in the game is 8.

Car size is FIT x rowPitchWu x pxPerWu, and rowPitchWu is 26/gridRows. So:
    gridRows 16 -> rowPitch 1.625 wu
    gridRows  8 -> rowPitch 3.250 wu
Exactly double. L1-L3 were rendering every car at HALF the size the rest of the
game uses, which is precisely what "the motorbikes are tiny" describes.

This is fallout from the L9-L40 conversion: L4-L8 were the pilot, L9-L40 were
converted on 2026-08-08, and L1-L3 were explicitly held back as out of scope both
times. They were the last levels on the old board. The whole game is now one depth.

Sim after the change (400 runs), all still in band:
    L1  100.0%   (85-100)
    L2   97.3%   (85-100)
    L3   92.3%   (85-100)
The 40-level flag set is unchanged: L4 TOO EASY, L30 BOSS, L39 TOO HARD — the same
three as before, so nothing else moved.

tests/regression-level-start.test.js's gridRows invariant is now simply
"expect(cfg.gridRows).toBe(8)" for every level, instead of carrying an exception.

===============================================================================
2. THE FTUE HAND IS CUT — NOT A CODE BUG. THE ASSET IS CLIPPED.
===============================================================================
This is NOT a mask, a container bound, or a layout error. The source PNG is
already cropped, and the renderer is faithfully drawing a clipped texture.

    public/sprites/ui/icon-hand.png   128x128
    opaque bounding box:  x 3..123,  y 0..127
    gaps:  top 0   bottom 0   left 3   right 4

The artwork touches the top and bottom edges with ZERO padding. See 03: the index
fingertip ends in a flat horizontal edge with no dark outline across it, while the
outline wraps every other side of the hand. Same at the bottom, where the blue
cuff is sliced. A complete sprite would have its stroke closing around the
fingertip. Those pixels are not in the file.

I searched the repo for an unclipped source. There is none — the only hand art is
this file. Padding the canvas would not help: the tip is missing, not merely flush.

TWO WAYS FORWARD, BOTH NEEDING YOUR CALL:
  a) Re-author icon-hand.png with the fingertip intact and ~10% padding, matching
     the other icons (icon-car and icon-book carry 13-15px gaps).
  b) Point this one call site at the emoji fallback that uiIcon already supports
     ('hand', 48, U+1F446), which renders a complete hand — but it will not match
     the rest of the designed icon set.

I did not pick one, because replacing or bypassing game art is a design decision,
not a bug fix. Nothing about the hand was changed in this batch.

NOTE: the same icon is used by TutorialOrchestrator at size 28, so whichever way
this goes, it fixes both call sites at once.
